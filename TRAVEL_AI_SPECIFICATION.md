# AI Tourism Smart Planner: Production Architecture Specification

## ⚙️ System Overview
A full-stack, production-ready Smart Tourism Web Application designed to fetch accurate real-world place data, utilize free/open AI models, and generate optimized, weather-aware travel itineraries.

**Technology Stack:**
*   **Frontend:** Next.js, Tailwind CSS
*   **Backend:** Python (FastAPI)
*   **Database:** PostgreSQL
*   **AI/LLM:** Free Local (Ollama) or Free API (Groq)
*   **Deployment:** Dockerized (Vercel for Frontend, Railway/Render/Fly.io for Backend)

---

## 1️⃣ Accurate Real-World Place Data (Mandatory)
The system strictly prohibits mock data or hallucinated locations. All recommendations must be fetched dynamically from real-world APIs.

**Primary Data Sources (Free):**
*   **OpenStreetMap (Overpass API):** Core geospatial data and POI retrieval.
*   **OpenTripMap API (Free Tier):** Tourist attraction categorization.
*   **GeoNames API:** Geographical database integration.
*   **Wikipedia API:** Contextual descriptions for historical/cultural sites.
*(Optional: Google Places API if a user-provided key is available).*

**Dynamic Data Requirements per Location:**
*   Place Name
*   Exact Latitude & Longitude
*   Category/Type
*   Rating (if available)
*   Description
*   Physical Address
*   Opening Hours (if available)

---

## 2️⃣ Free LLM Integration (Mandatory)
The application utilizes free-tier or open-source LLMs to provide natural language generation. **Crucially, the LLM does not perform the algorithmic routing or scoring; it strictly acts as the presentation and contextualization layer.**

**Supported Models:**
*   **Local/Self-Hosted (Preferred):** Ollama (Llama 3 8B, Mistral 7B, or Phi-3 Mini)
*   **Cloud API (Free Tier):** Groq, OpenRouter (Free models), or HuggingFace Inference API.

**LLM Responsibilities:**
*   Generate natural language itinerary summaries.
*   Explain *why* specific attractions were selected based on user interests.
*   Provide local travel tips and cultural context.
*   Suggest food recommendations relative to the route.
*   Add relevant safety advice.

---

## 3️⃣ AI / ML Logic (Free Models)
The core routing and recommendation engine relies on standard, high-performance machine learning and algorithmic libraries.

**Core Stack:**
*   `scikit-learn`
*   **KMeans Clustering:** To group attractions geographically by day.
*   **Haversine Distance Formula:** For accurate geospatial distance calculations.
*   **Nearest Neighbor Optimization:** For daily route sequencing.
*   **Weighted Scoring System:** Matrix computation prioritizing user interests and environmental factors.
*(Optional: XGBoost or LightGBM for advanced preference prediction).*

## 6️⃣ Core Itinerary Algorithm workflow
The central pipeline for generating an optimized travel plan:

1.  **Fetch Real Attractions:** Pull data from external APIs based on the destination.
2.  **Filter by Interests:** Remove POIs that do not match the user's selected preferences.
3.  **Score Locations:** Apply the weighted scoring formula:
    `score = (interest_match * 0.4) + (rating_weight * 0.2) + (distance_weight * 0.2) + (weather_suitability * 0.2)`
4.  **Cluster by Area:** Use KMeans to group the top-scoring attractions into daily clusters.
5.  **Assign to Days:** Distribute clusters across the requested trip duration.
6.  **Optimize Route:** Run a nearest-neighbor algorithm within each day's cluster to minimize transit time.
7.  **Calculate Sustainability:** Compute the carbon footprint and Eco-Score for the finalized route.
8.  **Generate Summary:** Pass the structured itinerary to the LLM for natural language enrichment.
9.  **Return JSON:** Respond via the API with the highly structured, optimized travel plan.

---

## 7️⃣ Weather Integration
*   **Provider:** OpenWeather (Free Tier).
*   **Impact:** Modulates the `weather_suitability` algorithmic score. Flags extreme conditions and structurally adjusts the itinerary to favor indoor activities during adverse weather.

---

## 8️⃣ Sustainability Engine
Computes the ecological impact of the generated itinerary to promote responsible tourism.

**Calculations:**
*   Total estimated travel distance.
*   Walking vs. Vehicle ratio.
*   Carbon emission estimate based on transit modality.
*   **Eco-Score (0–100):** Displayed prominently on the frontend as a Sustainability Badge.

---

A relational structure designed for performance with proper indexing.

**Primary Tables:**
*   `Users`
*   `Attractions` (Cached POI data to reduce API calls)

*   `ItineraryItems` (Foreign key relations to specific days and attractions)
